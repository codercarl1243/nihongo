## System Overview
"nihongo" is a local, privacy-first, voice-interactive Japanese language learning application (focused on JLPT preparation) built using the Tauri (v2) framework and a Rust workspace architecture. The system employs a modular Model-View-Controller (MVC) pattern, integrating a React/Vite/TypeScript frontend—which utilizes a component-based architecture and a hierarchical CSS Cascade Layer system to manage style specificity—with a multi-crate Rust backend comprising `tutor` (orchestration), `audio_engine` (signal processing), `db` (persistence), and `llm` (model interaction). The architecture is asynchronous and event-driven, utilizing `tokio` for a real-time interaction pipeline that includes Automatic Speech Recognition (ASR), Large Language Model (LLM) processing, and Text-to-Speech (TTS) synthesis. Heavy machine learning inference is offloaded to external sidecar processes—specifically a Python-based service (running FastAPI and MLX) and VoiceVox—communicated with via HTTP and Server-Sent Events (SSE) on `localhost:8091`. The sophisticated audio pipeline leverages `cpal`, `rubato` for FFT-based resampling, and `webrtc-audio-processing` to support Acoustic Echo Cancellation (AEC), Voice Activity Detection (VAD) via Silero, and barge-in detection.

## Module Groups

**Frontend UI & Design System**
Purpose: Implements the visual layer through a component-based architecture and a hierarchical CSS Cascade Layer (`@layer`) system. It manages design tokens, primitives, and semantic styles via the `coder-design` layer, component-level styles (e.g., `chatWindow`, `indicators`), and utility classes for animations and layout. Real-time session indicators and pipeline debugging are managed using a centralized Zustand store and `global.css`.
Files: `src/`, `src/components/`, `src/design-system/`, `src/styles/`, `src/lib/store.ts`, `src/lib/api.ts`, `src/main.tsx`, `src/App.tsx`

**Tauri Application Core & Security**
Purpose: Manages the desktop application lifecycle, the exposure of async commands (`commands.rs`) and event structures (`events.rs`) to the frontend, the central `AppState` container, and the capability-based security model for window access and permissions.
Files: `Cargo.toml`, `tauri.conf.json`, `src-tauri/src/lib.rs`, `src-tauri/src/main.rs`, `src-tauri/src/commands.rs`, `src-tauri/src/events.rs`, `src-tauri/capabilities/default.json`

**AI Sidecar & Process Management**
Purpose: Handles the spawning, health monitoring, and graceful shutdown of external Python-based MLX and VoiceVox processes. It provides the client implementation for communicating with these services via HTTP/SSE, managing ASR transcription, LLM chat, and tracking token usage.
Files: `src-tauri/crates/llm/` (`client.rs`, `lib.rs`), `src-tauri/src/sidecar.rs`, `server.py`, `models.py`, `sidecar/start.sh`

**Audio Processing Engine**
Purpose: A real-time signal processing pipeline that manages the lifecycle of audio I/O via `cpal`. It orchestrates the flow between microphone capture, resampling (via `rubato`), Acoustic Echo Cancellation (AEC) via `webrtc-audio-processing`, Voice Activity Detection (VAD) via Silero, and playback.
Files: `src-tauri/crates/audio_engine/` (`lib.rs`, `manager.rs`, `capture.rs`, `player.rs`, `aec.rs`, `resampler.rs`, `barge_in.rs`, `vad.rs`)

**Text-to-Speech (TTS) Orchestration**
Purpose: Manages the selection and execution of different speech synthesis engines (Qwen3 and VoiceVox) through a unified `TtsEngine` enum and asynchronous HTTP communication via `reqwest`.
Files: `src-tauri/src/tts/` (`mod.rs`, `qwen3.rs`, `voicevox.rs`)

**Tutor Orchestration & Interaction Pipeline**
Purpose: The core pedagogical engine. It manages the end-to-end interaction flow (audio input $\rightarrow$ transcription $\rightarrow$ LLM $\rightarrow$ speech synthesis), including message history, token counting, and language-specific instructional logic (proficiency levels N5-N2).
Files: `src-tauri/crates/tutor/src/` (`lib.rs`, `language.rs`, `session.rs`, `prompt.rs`, `types.rs`), `prompts/`, `src-tauri/src/pipeline.rs`, `src-tauri/src/greeting.rs`

**Data Persistence**
Purpose: Manages local SQLite persistence for user vocabulary, learner profiles, session history, kanji, and curriculum progress using a repository-style pattern.
Files: `src-tauri/crates/db/` (`lib.rs`, `store.rs`, `types.rs`, `seed.rs`), `rusqlite`

**Test, Infrastructure & Utilities**
Purpose: Implements low-level text manipulation, error handling, and logging, while providing specialized binaries, scripts for integration testing, and managing Python environment deployment and assets.
Files: `lib/`, `src/bin/`, `scripts/`, `start.sh`, `requirements.txt`, `public/`, `src/assets/`
