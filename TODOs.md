## Phase 2 — Barge-In Refactor + Tests

> **Why:** TTS audio is being cut off prematurely even with AEC. The barge-in logic is inline in `manager.rs:run_loop()` — 200+ lines of atomic state and streak counters that can't be tested without real hardware. Extract it so we can test every edge case deterministically.

### 2a. Extract `BargeInDetector` + `EchoTailTracker`

**New file:** `src-tauri/crates/audio_engine/src/barge_in.rs`

```rust
pub struct BargeInDetector {
    streak: u32,
    confirmed: bool,
    buffer: Vec<f32>,
    streak_required: u32,
    rms_threshold: f32,
    start_delay_ms: u64,
    audio_started_ms: u64,   // 0 = audio hasn't played yet
}

impl BargeInDetector {
    pub fn new(streak_required: u32, rms_threshold: f32, start_delay_ms: u64) -> Self
    pub fn signal_audio_started(&mut self, now_ms: u64)  // idempotent
    pub fn reset(&mut self)                               // call on mute()
    pub fn is_active(&self, now_ms: u64) -> bool         // delay elapsed?
    pub fn process_chunk(&mut self, chunk: &[f32], is_speech: bool, now_ms: u64) -> BargeInState
    pub fn take_buffer(&mut self) -> Vec<f32>
}

pub enum BargeInState {
    Suppressed,      // delay not yet elapsed
    BelowGate,       // rms < threshold
    Streak(u32),     // building toward required count
    Confirmed,       // first frame that crossed threshold — set atomic flag here
    Buffering,       // already confirmed, keep accumulating
}

pub struct EchoTailTracker {
    suppress_until: Option<Instant>,
    duration: Duration,
}

impl EchoTailTracker {
    pub fn new(duration: Duration) -> Self
    pub fn arm(&mut self)
    pub fn is_active(&self) -> bool
    pub fn disarm(&mut self)
}
```

**`manager.rs` changes:**
- Replace inline streak/buffer/echo-tail variables with `BargeInDetector` + `EchoTailTracker` instances
- `AudioManager::signal_audio_started()` delegates to `detector.signal_audio_started(now_ms)`
- `AudioManager::mute()` calls `detector.reset()` in addition to setting the atomic
- On unmute: call `detector.take_buffer()` to get any buffered barge-in audio
- `lib.rs` re-exports both types from `audio_engine`

### 2b. Unit tests for `BargeInDetector` (in `barge_in.rs` `#[cfg(test)]`)

All tests pass fake `now_ms` — **no clock dependency, no hardware needed**.

| Test | What it verifies |
|------|-----------------|
| `suppressed_before_delay_elapsed` | `is_active()` false when `now - started < delay` |
| `active_after_delay_elapsed` | `is_active()` true when delay passes |
| `rms_below_gate_does_not_build_streak` | chunk rms < threshold → `BelowGate`, streak stays 0 |
| `streak_builds_on_successive_speech_chunks` | 5 loud+speech chunks → `Streak(5)` |
| `confirmed_at_streak_required` | 6th chunk → `Confirmed`, buffer fills |
| `streak_resets_on_one_quiet_chunk` | 5 loud then 1 quiet → streak back to 0 |
| `confirmed_buffers_subsequent_chunks` | After `Confirmed`, next chunk → `Buffering` |
| `buffer_cleared_on_reset` | `reset()` clears buffer, streak, confirmed flag |
| `signal_audio_started_is_idempotent` | Second call with different `now_ms` keeps original timestamp |
| `echo_tail_arms_and_expires` | `arm()` → `is_active()` true; after `duration` → false |
| `echo_tail_disarm_cancels` | `disarm()` → `is_active()` false immediately |

### 2c. AEC integration tests

**New file:** `src-tauri/crates/audio_engine/src/tests/aec_barge_in.rs`

Uses `AecSink` + `AecProcessor` directly — **no hardware, no sidecar**.

**Test 1 — AEC residual is below the barge-in gate:**
```
1. create_aec_pair()
2. Generate 1s of loud sine (rms ~0.15) at 16kHz → simulate TTS speaker output
3. Push all frames through AecSink (TTS reference path)
4. Feed the same frames as "mic input" through AecProcessor::process_in_place()
5. Measure output RMS
6. Assert output_rms < 0.025 (barge_in_rms_threshold)
   ← proves AEC cancels its own echo below the gate
```

**Test 2 — Real user speech is NOT suppressed below the gate:**
```
1. create_aec_pair()
2. Push 0.5s silence as TTS reference (no echo in reference)
3. Feed 0.5s loud sine as mic input (user speaking)
4. Run through AecProcessor::process_in_place()
5. Assert output_rms > 0.025
   ← proves genuine speech still clears the gate
```

**Test 3 — BargeInDetector + AEC pipeline (end-to-end, no hardware):**
```
1. BargeInDetector(streak=6, rms_threshold=0.025, delay=0ms)
2. signal_audio_started(now=0)
3. Feed 10 chunks of AEC-cancelled echo (rms < 0.025) → never Confirmed
4. Feed 6 chunks of real speech (rms > 0.05) → Confirmed on 6th
```

**Test 4 — TTS playback echo does not trigger barge-in (combined):**
```
1. Create AudioPlayer + AecSink + BargeInDetector
2. Play 2s sine buffer through player (simulates TTS)
3. Feed player output back as mic input through AEC (simulates room echo)
4. Run all AEC-processed chunks through BargeInDetector
5. Assert barge_in never Confirmed
```

## Phase 5 — Multi-Language Architecture

> **Why:** The project is a Japanese tutor but the codebase should be able to teach any language. All Japanese-specific logic (JLPT levels, kanji/hiragana constraints, drill keywords, TTS voice) is hardcoded in the `tutor` crate. Extracting it into a `LanguageConfig` trait makes every language a first-class citizen.

### What is Japanese-specific today

| Location | Coupling |
|----------|---------|
| `tutor/src/prompt.rs` | JLPT level descriptions, kanji/hiragana/katakana script constraints |
| `tutor/src/session.rs` | `is_drill_prompt()` checks Japanese keywords (言ってみて, etc.) |
| `src-tauri/src/lib.rs` | Silence thresholds mapped to JLPT levels (N1–N5 → 700/900/1200ms) |
| `db/src/schema.rs` | `kanji` table, `reading` (furigana) column |
| `Models.json` | `Ono_Anna` TTS voice (Japanese), `Qwen3-ASR` (Japanese-tuned) |
| `sidecar/server.py` | `voice = "Ono_Anna"` hardcoded |

### `LanguageConfig` trait

**New file:** `src-tauri/crates/tutor/src/language.rs`

```rust
pub trait LanguageConfig: Send + Sync {
    fn language_code(&self) -> &str;                    // "ja", "es", "fr", "zh"
    fn language_name(&self) -> &str;                    // "Japanese", "Spanish"
    fn level_count(&self) -> u8;                        // 5 for JLPT, 6 for CEFR
    fn level_name(&self, level: u8) -> &str;            // "N5", "A1"
    fn level_description(&self, level: u8) -> &str;
    fn instruction_for_level(&self, level: u8) -> &str; // prompt fragment
    fn silence_threshold_ms(&self, level: u8) -> u64;
    fn is_drill_prompt(&self, response: &str) -> bool;
    fn tts_voice(&self) -> &str;
}
```

**Concrete implementation:** `src-tauri/crates/tutor/src/languages/japanese.rs`

Moves `INSTRUCTION_LANGUAGE_*` constants and `is_drill_prompt` out of `prompt.rs` / `lib.rs` into `Japanese` struct methods.

`TutorSession` accepts `Arc<dyn LanguageConfig>`. Existing Japanese behaviour is **unchanged** — adding Spanish requires only a new struct + prompt files.

### Branching strategy

- `main`: current Japanese-only code (do not break)
- `feat/language-config`: adds trait + `Japanese` impl
- Language branches (`feat/lang-spanish`, etc.) added later by the same pattern

### DB: add `language_code` column

Add `language_code TEXT NOT NULL DEFAULT 'ja'` to `curriculum`, `vocabulary`, `student_vocabulary`. The `kanji` table stays Japanese-only (other languages skip it). DEFAULT preserves all existing rows.

## Phase 6 — Journal Feature

> **Why:** Personal vocabulary (words anchored to the learner's own experiences) has significantly higher retention than abstract word lists. The journal lets a learner write freely; the LLM identifies which words are worth adding to their SRS deck.

### Data model

```sql
CREATE TABLE journal_entries (
    id            INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id    INTEGER REFERENCES sessions(id),
    language_code TEXT NOT NULL DEFAULT 'ja',
    created_at    TEXT NOT NULL DEFAULT (datetime('now')),
    body          TEXT NOT NULL
);

CREATE TABLE journal_words (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    entry_id     INTEGER NOT NULL REFERENCES journal_entries(id),
    word         TEXT NOT NULL,
    reading      TEXT,           -- furigana / phonetic (language-dependent)
    meaning      TEXT NOT NULL,
    added_to_srs INTEGER NOT NULL DEFAULT 0
);
```

### Journal extraction prompt

**New file:** `prompts/journal-extractor.txt`

```
You are a vocabulary extractor for a {language} language learner at {level_name} level.
Given the journal entry below, identify words that would be valuable to add to the
learner's spaced-repetition deck. Prefer words the learner actually used.
Return ONLY a JSON array, no prose:
[{"word": "...", "reading": "...", "meaning": "...", "relevance": "..."}]
Limit to 10 words maximum. Return [] if no useful vocabulary found.
```

### Rust: `tutor/src/journal.rs`

```rust
pub async fn extract_journal_words(
    entry: &str,
    lang: &dyn LanguageConfig,
    level: u8,
    llm: &LlmClient,
) -> Result<Vec<JournalWord>>
// Uses existing /llm/chat endpoint, single-turn, no streaming
// Falls back to [] on JSON parse failure (same pattern as session summarizer)
```

### Tauri command

`invoke('add_journal_words', { words, entry_id })` → `db::add_vocabulary_from_journal()` → inserts into `vocabulary` + `student_vocabulary` at fluency_level 0.

### Frontend: `src/components/journal/`

```
src/components/journal/
  index.tsx       ← <JournalEntry> component
  useJournal.ts   ← submission state + extracted word approval
```

**Layout notes:**
- `<textarea>` for free-form writing — plain HTML (Inline/Stack don't handle resizable text areas; recommend a `<Textarea>` primitive)
- `<Button>` (existing design system) to submit
- Extracted words displayed as `<Badge>` chips (Phase 4a)
- "Add to deck" per-word toggle uses `<Switch>` (existing design system)
